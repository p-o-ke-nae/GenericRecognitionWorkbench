# 汎用自動認識ツール概要

## 構成

- Recognition.Core
  - 画像認識・OCR の中核です。
  - ここには認識結果の型、認識設定、ROI、前処理設定、OCR オプション、認識実行のインターフェースを置きます。
  - 重要なのは、この層に WPF やアプリ固有のカウンター処理を入れないことです。
- Recognition.Infrastructure
  - 実際の OCR エンジンや画像処理ライブラリへの依存を閉じ込めます。
  - たとえば OpenCV、Tesseract、NDLOCR-Lite、PaddleOCR、JSON/SQLite への設定保存、画面キャプチャやカメラ入力の実装はここです。
  - Recognition.Core のインターフェース実装だけを担当させます。
- Recognition.Wpf
  - 認識設定用の共通 GUI です。
  - ROI 編集、プレビュー、しきい値調整、OCR 言語選択、テスト実行、結果確認などをここにまとめます。
  - Window そのものではなく、再利用可能な UserControl と ViewModel のライブラリにしておくと、複数アプリから埋め込めます。
- AutoCountTool
  - このリポジトリのカウンターツール本体です。
  - カウンター表示、手動増減、自動認識の ON/OFF、認識イベントを受けて count を増減する処理はここに置きます。
  - 認識ワークベンチは別ウィンドウで開きますが、アプリのメインフォームはカウンター側とします。

## 汎用部分と本ツール固有部分の境界

| 区分 | 置き場所 | 役割 |
| --- | --- | --- |
| 汎用自動認識エンジン | `Recognition.Core` / `Recognition.Infrastructure` | フレーム取得、前処理、テンプレートマッチング、OCR、距離計測、認識イベント判定 |
| 汎用認識 GUI | `Recognition.Wpf\\RecognitionWorkbenchControl` とその ViewModel 群 | 認識設定編集、プレビュー、テスト実行、開始停止、プロファイル保存 |
| 本カウンターツール固有 GUI | `AutoCountTool\\MainWindow.xaml` | カウンター表示、手動 +/-、自動認識 ON/OFF、目標値、常に手前表示 |
| 本カウンターツール固有の自動処理 | `AutoCountTool\\CounterAutomationController.cs` | 認識イベントを受けて count を増減するロジック |
| 本アプリでの認識画面のホスト | `AutoCountTool\\RecognitionWorkbenchWindow.xaml` | 汎用 `RecognitionWorkbenchControl` を別ウィンドウとして開く薄いラッパー |

## GUI のすみわけ

- **MainWindow**
  - カウンター専用のメインフォームです。
  - ユーザーが常時触るのはここで、数値表示、目標、手動調整、自動認識の有効化を担当します。
- **CounterAutomationSettingsWindow**
  - カウンター向けの簡易自動認識設定画面です。
  - プロファイル、キャプチャ、前処理、判定用テンプレート、FPS、プレビューに絞って設定します。
  - 詳細が必要な場合だけ汎用の認識ワークベンチを開きます。
- **RecognitionWorkbenchWindow**
  - 認識設定専用の別ウィンドウです。
  - 中身の実体は `Recognition.Wpf` の汎用 `RecognitionWorkbenchControl` で、他プロジェクトでも再利用できます。
- **OCR**
  - OCR 基準点と OCR 対象は別々に設定します。
  - OCR 基準点は `OCR 基準点` の一覧で管理し、OCR 対象はその名前を参照して相対位置を持ちます。
  - OCR 対象で **相対位置を使う** ときだけ、OCR 基準点名を選択します。
  - 相対位置を使わない場合は、OCR 基準点名は不要で、OCR 領域は絶対座標として扱います。
  - OCR 対象の X/Y は負値も指定でき、基準点の左上より左・上側も表現できます。
  - OCR 基準点は未設定でもよく、OCR 対象だけを絶対座標で置けば通常の OCR として使えます。
- つまり、**GUI の境界は「日常運用のカウンター UI は AutoCountTool 側」「認識設定 UI は Recognition.Wpf 側」** です。

## 画像認識による自動カウントアップ処理の記述場所

- 本ツール固有の自動カウントアップ / カウントダウン処理は、`AutoCountTool\\CounterAutomationController.cs` の `ApplyRecognitionResult` に記述します。
- このメソッドは `RecognitionWorkbenchWindow` から流れてくる `RecognitionEventRaised` を `MainWindow` が受け、その結果を渡して呼び出します。
- `Recognition.*` 側には count の概念を持ち込まず、**「認識イベントを出すまで」が汎用、「そのイベントで count をどう変えるか」が本ツール固有** という分離にします。

## 要件

- 動画をキャプチャし，毎秒60回以上画像認識による判定ができること
  - 認識ループのfpsはGUIから指定できること
  - どのキャプチャソースでも共通で入力画像の倍率をGUIから指定できること
  - 共通倍率は認識処理とプレビューに同じ画像として反映されること
  - プレビューは，キャプチャ映像表示，画像処理後表示，OCR エリア表示をGUIから切り替えられること
  - プレビューは，距離計測結果表示モードもGUIから切り替えられること
  - プレビューには画像認識結果を重ねて表示でき，最も一致した領域を赤枠で示せること
  - OCR エリア表示では，全体画像の中で各 OCR 対象領域がどこか分かる形で，文字認識時に実際に使用した画像処理後の各 OCR 画像を重ねて表示できること
  - OCR エリア表示は文字認識が実行されたときのみ更新すること
  - OCR エリア表示では，どの OCR 領域かを示すラベルの表示/非表示をGUIから切り替えられること
  - 距離計測結果表示では，距離計測に実際に使用した画像を表示し，基準点とターゲットを枠で表示し，距離とラベルの表示/非表示をGUIから切り替えられること
  - 距離計測結果表示では，ビューアにホバーしたカーソル位置までの距離を，各基準点ごとにプレビュー内へ重ねて表示でき，その表示/非表示をGUIから切り替えられること
- 動画のキャプチャの手段はIFを設けること
  - キャプチャ用ウィンドウによる領域指定と，カメラ入力による取得を作成すること
  - カメラ入力は可能であればカメラ番号ではなくカメラ名のプルダウンから選択できること
  - テスト用に，画像ファイルを入力として扱うキャプチャコンポーネントを用意すること
  - 動的コンポーネント読込に対応させて，ユーザーがnugetで公開されたIFから自作できること
  - 各種パラメータはGUIから指定できること
  - キャプチャ側が持つfps等のパラメータもGUIから指定できること
- 画像認識の手段はIFを設けること
  - テンプレートマッチングによる認識を作成すること
  - テンプレート画像はキャプチャ画像の生画像と画像処理後画像の両方から，任意のエリアをトリミングして作成できること
  - GUI 上で画像を指定する全ての箇所は，生画像・画像処理後画像の両方から任意エリアを切り出して作成できること
  - GUI 上で画像を指定する全ての箇所は，ファイル選択ダイアログからも画像を選択できること
  - プロファイルは 1 設定につき 1 フォルダで保存し，設定 json と画像を階層分離して保存できること
  - プロファイル内の画像パスは相対パスで扱え，他環境でもそのまま利用できること
  - テンプレートマッチング設定は，環境差に合わせて自動調整し，新たなプロファイルとして保存できること
  - 各種パラメータはGUIから指定できること
  - 動的コンポーネント読込に対応させて，ユーザーがnugetで公開されたIFから自作できること
  - 画像認識時のイベントは呼び出し側のツールによって指定できること
    - 例として，カウントアップであれば否認識→認識の瞬間，ゲーム画面の数値読込であれば認識→否認識の瞬間，追跡であれば認識の間
  - プレビュー上に最も一致した領域を表示でき，認識時は赤枠，未認識時は青枠で示せること
  - 認識イベント時の処理として，OCR と距離計測を選択できること
  - 認識イベント時の OCR / 距離計測の対象フレームとして，最新フレームだけでなく数コマ前 / 数コマ後の画像も指定できること
  - 距離計測では，複数の基準点テンプレートと複数のターゲットテンプレートを指定できること
  - 各ターゲットは，どの基準点に対する距離を測るかを個別に指定できること
  - 距離計測では，対象ターゲットに紐づく基準点テンプレートとそのターゲットテンプレートの両方が閾値を超えたものだけについて，x座標差分とy座標差分を計算できること
- 画像処理の手段はIFを設けること
  - 任意の領域を切り出すトリミング前処理を作成すること
  - 反転と輪郭抽出の前処理を追加すること
  - 動的コンポーネント読込に対応させて，ユーザーがnugetで公開されたIFから自作できること
  - 各種パラメータはGUIから指定できること
- 文字認識の手段はIFを設けること
  - 動的コンポーネント読込に対応させて，ユーザーがnugetで公開されたIFから自作できること
  - 各種パラメータはGUIから指定できること
  - TesseractOCR，PaddleOCRによる認識を作成すること
  - OCR は複数箇所を設定でき，各箇所ごとに個別の画像処理を設定できること
- 情報抽出用の画像認識について
  - OCR や距離計測と同様に、**名前付きの複数ターゲット** を持てるモジュールとして扱う
  - 各ターゲットは個別の画像認識設定と前処理を持てること
  - 結果はターゲット名をキーとした JSON 構造で呼び出し元へ渡す
- GUI は日本語表記を持ち，言語切替に対応すること
  - デフォルト表示言語は日本語とすること
- 自動認識ツールとは別に，画像認識イベントと連携して増減できるカウンター UI を持つこと

## プロファイル保存規約

- プロファイルは **1プロファイル = 1フォルダ** とする
- プロファイル保存先の親フォルダは、アプリ直下の **`Profiles`** フォルダとする
- プロファイルフォルダ名はプロファイル名をベースに決める
- プロファイル設定ファイル名は必ず **`profile.json`** とする
- プロファイルで使う画像は、そのプロファイルフォルダ配下の **`images`** フォルダ以下に配置する
- プロファイル内の画像パスは、プロファイルフォルダ基準の相対パスとして保存する
- 読込時は `Profiles` 配下のプロファイル一覧をロードし、GUI のプルダウンから選択する
- 保存時はパスを手入力せず、現在のプロファイル名に対応する `Profiles\\<ProfileName>\\profile.json` へ保存する
- これにより、他ユーザーが作成したプロファイルも **フォルダ単位で受け入れれば競合しない**

## GUI設定箇所

- 認識イベントの発火条件は，**プロファイル** セクションの **イベント条件** で指定する
- OCR / 距離計測を行うかどうかは，**プロファイル** セクションの有効化チェックで個別に切り替える
- 認識イベント時に何コマ前 / 後の画像を OCR / 距離計測に使うかは，**プロファイル** セクションの **イベント処理フレームオフセット** で指定する
- OCR を使うか，どの OCR エンジンを使うか，OCR 基準点と OCR 領域をどう対応付けるか，各 OCR 領域とその個別前処理をどう設定するかは，**OCR** セクションで指定する
- 距離計測で使う複数の基準点テンプレート，複数のターゲットテンプレート，ターゲットごとの基準点名，それぞれの閾値は，**距離計測** セクションで指定する
- 複数の前処理，OCR 基準点，OCR 対象，距離計測基準点，距離計測ターゲット，情報抽出用画像認識ターゲットは，各一覧の **↑ / ↓** ボタンで実行順・評価順を並べ替える
- 環境差に合わせたテンプレートマッチングの自動調整と新規プロファイル保存は，**操作** セクションの **環境向けに自動調整して保存** から行う
- OCR 基準点の確認は，**プレビュー表示** の **OCR 基準点** モードで行う
- プレビュー固有の設定は，**プロファイル** セクションの **プレビュー設定** で，選択中プレビューモジュールごとに切り替える
- 単発テストでは，認識イベントの発火有無に関係なく，現在フレームに対して OCR / 距離計測のプレビュー確認を行う
- OCR や距離計測は，項目を 1 件以上作らなくてもよく，**0 件のまま保存・再読込しても維持される**

## プレビューモジュール拡張

- `Recognition.Wpf` では，プレビュー描画を `IPreviewModule` で差し替え・追加できる
- 組み込みでは，キャプチャ映像，画像処理後，OCR 基準点，OCR エリア，距離計測を個別モジュールとして登録する
- 各モジュールは，必要なプレビュー設定（ラベル表示や距離ホバー表示など）だけを `PreviewSettings` に公開する

## 認識結果の受け渡し

- 汎用認識側は、判定・OCR・距離計測の結果を **JSON 文字列** として `RecognitionCycleResult` に載せて呼び出し元へ渡します。
- JSON は少なくとも次のトップレベルを持ちます。
  - `detection`
  - `ocr`
  - `distanceMeasurement`
  - `imageRecognition`
- `ocr` と `distanceMeasurement` は **ターゲット名をキー** とした構造です。
- `imageRecognition` も **ターゲット名をキー** とした構造です。
- 呼び出し元ツール側は、この JSON を解釈してイベントや業務処理を定義する責務を持ちます。

## 日本語 OCR の選定とチューニング

- まず試す候補は **NDLOCR-Lite** です。国立国会図書館が公開している CPU 実行可能な日本語 OCR で、図書・雑誌・縦書きに強く、2026 年の公開版では手書き強化も入っています。
- 次点は **PaddleOCR 日本語** です。2026 年時点では PP-OCRv6 系が日本語を含む 50 言語対応となっており、印字・画面表示・業務帳票では有力です。複雑レイアウト全体まで扱うなら PaddleOCR-VL 系も候補です。
- **Tesseract OCR Japanese Best** は安定重視の代替です。`tessdata_best` を使い、`jpn` / `jpn_vert` / `jpn+eng` を切り替えて調整します。

### OCR 基準点マッチングの入力画像

- OCR 基準点マッチングは、**キャプチャ倍率適用後の生画像** を **グレースケール化した画像** に対して行います。
- ここでは、共通前処理（トリミング、二値化、反転、輪郭抽出など）や OCR 対象ごとの前処理は **適用しません**。
- そのため、OCR 基準点テンプレートは **生画像から作成するのが基本** です。
- 実運用では、**プレビュー表示 = OCR 基準点** に切り替えると、現在の最良一致位置と一致度合いを確認できます。

### チューニングの流れ

1. OCR 対象をできるだけ小さい領域に切り出す。
2. OCR 基準点を使う場合は、まず **生画像から** 基準点テンプレートを切り出し、**OCR 基準点プレビュー** で一致度を確認する。
3. 必要なら OCR 対象ごとの前処理でグレースケール、二値化、反転、輪郭抽出を試す。
4. 日本語エンジンを **NDLOCR-Lite → PaddleOCR → Tesseract** の順で比較する。
5. PaddleOCR を使う場合は、縦横向き補正、対象 ROI の縮小、二値化有無、辞書/文字種の絞り込みを優先して見直す。
6. NDLOCR-Lite を使う場合は、縦中横補正の有無や対象画像の切り出し粒度を見直す。
7. 認識が不安定なら、閾値・前処理・対象サイズ・縦横向きを順に見直す。
8. 良い組み合わせが見つかったら、プロファイルとして `Profiles\\<ProfileName>\\profile.json` と画像一式で保存する。
